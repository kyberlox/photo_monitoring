# Виртуальная карта – Photo Monitoring

Проект для мониторинга фотографий по географическим локациям. Позволяет добавлять точки на карту, прикреплять к ним фотографии с комментариями и просматривать наблюдения.

## Архитектура

- **Бэкенд**: FastAPI + SQLAlchemy (асинхронный) + PostgreSQL
- **Фронтенд**: (планируется) React/TypeScript с картами
- **Инфраструктура**: Docker Compose, Nginx
- **Хранение файлов**: Файлы сохраняются на диск, обслуживаются через статику FastAPI

## Функциональность

### Сущности

1. **Локация (Location)**
   - Координаты (массив [X, Y])
   - Название (опционально)
   - Список прикреплённых фотографий

2. **Фото (Photo)**
   - Название
   - Комментарий (опционально)
   - Файл изображения (хранится на диске, путь в БД)
   - URL для доступа к файлу (`/static/photos/...`)
   - Дата создания
   - Связь с локацией

### API Endpoints

#### Локации
- `GET /locations/all` – список всех локаций (включая фото с URL)
- `GET /locations/id={id}` – получить локацию по ID (с фото)
- `POST /locations/add` – создать новую локацию (можно сразу загрузить фото через form data)
- `PUT /locations/id={id}` – обновить локацию (без фото)
- `DELETE /locations/id={id}` – удалить локацию и все её фото

#### Фото
- `GET /photos/all` – список всех фото (можно фильтровать по `location_id`)
- `GET /photos/id={id}` – получить фото по ID (с URL)
- `POST /photos/add` – загрузить новое фото (form data)
- `PUT /photos/id={id}` – обновить метаданные или заменить изображение (form data)
- `DELETE /photos/id={id}` – удалить фото

## Установка и запуск

### Требования

- Docker и Docker Compose
- Python 3.13 (для локальной разработки)

### Быстрый старт

1. Клонируйте репозиторий:
   ```bash
   git clone <repository-url>
   cd photo_monitoring
   ```

2. Создайте файл `.env` на основе `.env.example`:
   ```bash
   cp .env.example .env
   # Отредактируйте .env при необходимости
   ```

3. Создайте папку для загрузок (если не существует):
   ```bash
   mkdir -p uploads/photos
   ```

4. Запустите сервисы через Docker Compose:
   ```bash
   docker-compose up -d
   ```

5. Таблицы базы данных создаются автоматически при запуске приложения.

6. Откройте в браузере:
   - API документация: http://localhost:8000/docs
   - Основное приложение (через Nginx): http://localhost

### Локальная разработка (без Docker)

1. Установите зависимости:
   ```bash
   cd app
   pip install -r requirements.txt
   ```

2. Запустите PostgreSQL (например, через Docker):
   ```bash
   docker run --name postgres_async -e POSTGRES_USER=kyberlox -e POSTGRES_PASSWORD=gbljhfcbyf -e POSTGRES_DB=pdb -p 5432:5432 -d postgres:15-alpine
   ```

3. Создайте папку для загрузок:
   ```bash
   mkdir -p ../uploads/photos
   ```

4. Запустите сервер FastAPI:
   ```bash
   fastapi run app/main.py --port 8000
   ```

## Примеры использования API

### Создание локации с фото (form data)

```bash
curl -X POST http://localhost:8000/locations/add \
  -F "coord_x=55.7522" \
  -F "coord_y=37.6156" \
  -F "name=Москва, Красная площадь" \
  -F "photos=@/path/to/photo1.jpg" \
  -F "photos=@/path/to/photo2.jpg"
```

### Получение всех локаций с фото

```bash
curl http://localhost:8000/locations/all
```

Ответ будет содержать массив локаций, каждая с полем `photos`, где у каждого фото есть `file_url`:

```json
{
  "id": 1,
  "name": "Москва, Красная площадь",
  "coordinates": [55.7522, 37.6156],
  "photos": [
    {
      "id": 1,
      "title": "photo1.jpg",
      "comment": null,
      "created_at": "2026-04-03T05:30:00",
      "file_url": "http://localhost:8000/static/photos/abc123.jpg",
      "location_id": 1
    }
  ]
}
```

### Загрузка отдельного фото

```bash
curl -X POST http://localhost:8000/photos/add \
  -F "title=Закат" \
  -F "comment=Красивый закат над озером" \
  -F "location_id=1" \
  -F "file=@/path/to/sunset.jpg"
```

### Доступ к статическим файлам

Загруженные фото доступны по URL:
```
http://localhost:8000/static/photos/{filename}
```

Пример:
```bash
curl http://localhost:8000/static/photos/abc123.jpg
```

## Особенности реализации

### Хранение файлов

- Фотографии сохраняются на диск в папку `uploads/photos/`
- В базе данных хранится только путь к файлу (`file_path`)
- При загрузке клиент отправляет файл через `multipart/form-data` (поле `file` или `photos`)
- Сервер генерирует уникальное имя файла (UUID) и сохраняет его на диск
- Для доступа к файлу используется статический маршрут FastAPI `/static/`, который монтируется на папку `/uploads`
- При запросе фото через API возвращается полный URL (`file_url`) для доступа к файлу

**Важно**: Папка `uploads/` добавлена в `.gitignore` и не должна попадать в систему контроля версий.

### Асинхронность

- Все операции с базой данных используют асинхронные драйверы (asyncpg)
- FastAPI работает в асинхронном режиме для высокой производительности
- Загрузка файлов происходит асинхронно через `UploadFile`

### Автоматические миграции

- Таблицы создаются автоматически при запуске приложения через событие `startup` (см. `app/main.py`)
- Не требуется ручной запуск скриптов инициализации
- При ошибке подключения к PostgreSQL сервер делает несколько попыток с задержкой

### Безопасность

- CORS настроен для работы с фронтендом (разрешены все домены в разработке)
- В продакшене необходимо настроить ограничения
- Файлы сохраняются с уникальными именами, предотвращая перезапись
- Поддерживаются только изображения (расширения .jpg, .jpeg, .png, .gif, .bmp, .webp)
